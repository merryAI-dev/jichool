# 연차 조회·신청 준비·캘린더 등록

이 스킬은 jichool 저장소의 `leave_calendar.py`와 `expense.py`, 정상 로그인 세션,
사용자 Google Calendar 연결을 사용한다. 저장소와 함께 사용한다. 별도 DB는 없다.
완료 기준은 해당 상신 건의 캘린더 일정을 생성하고 재조회하여 링크를 반환하는 것이다.
백그라운드 감시나 승인·취소 동기화는 수행하지 않는다.

## 자연어 요청 분기

- “연차 얼마나 남았어?”, “올해 쓴 휴가 보여줘” → 아래 조회 명령을 실행한다.
  연도 생략 시 실행 시점의 서울 날짜를 사용한다. 금년을 코드나 기억에 고정하지 않는다.
  `python3 leave_calendar.py --action status --year YYYY`
  balance는 화면과 같은 부여(granted), 사용·예약 차감(used_or_reserved),
  결재진행(pending), 잔여(remaining)다. 미래 승인 휴가도 차감될 수 있으므로
  사용·예약 차감을 전부 이미 쉰 날이라고 설명하지 않는다. history의 기간과 상태로
  과거 사용/오늘 사용/향후 예약/결재진행을 구분한다. 반려·취소는 사용 실적에서 제외한다.
- “다음 주 금요일 오후반차 올려줘” → 현재 서울 날짜로 절대 날짜를 정하고 요일을 대조한다.
  “금요일” 등 해석이 모호하거나 연도가 불확실하면 질문한다. 조회 요청을 신청으로 해석하지 않는다.
  “오전 반반차”는 서버 항목 `반반차`와 구체적인 시작·종료 시간으로 풀되 시간이 없으면 질문한다.
  개인별 과거 시간을 회사 전체 기본값으로 적용하지 않는다.
  다음 구조의 JSON을 `.expense-state/` 아래에 권한 600으로 만든다.

  ```json
  {"type":"오후반차","start":"2030-01-07","end":"2030-01-07","reason":"사용자가 제공한 사유"}
  ```

  날짜는 예시다. 시간 직접 입력 항목에는 `start_time`, `end_time`을 HH:MM으로 추가한다.
  `python3 leave_calendar.py --action prepare --request PRIVATE_REQUEST --output NEW_PRIVATE_PLAN`
  결과의 실제 근무표 시간, 서버 차감 일수, 겹치는 신청, questions를 확인한다.
  휴일을 주말로만 계산하거나 사유를 임의로 “개인 사정”으로 채우지 않는다.
  **prepare는 상신하지 않는다.** `prepared_not_submitted`를 성공 상신으로 안내하지 않는다.
  사유는 서버 양식 설정에서 필수인 경우에만 반드시 묻는다. 선택 항목이며 사용자가
  문구를 주지 않았다면 비워 두고 그 사실을 안내한다.
- “임시저장해줘” → `python3 leave_draft.py --request PRIVATE_REQUEST --journal NEW_PRIVATE_JOURNAL`
  현재는 본인의 단일 연속 휴가 기간만 지원한다. 정상 양식·결재선과 원본 본문을 사용하고
  임시보관 상태를 재조회한다. 기존 작업은 같은 journal로 재개하며 새 journal로 중복 실행하지 않는다.
  `2001` 등 저장 오류가 나도 재조회로 문서·내용이 확인되면 성공 처리한다. 저장 결과가
  불명확하면 무조건 재전송하지 않는다. 임시저장만 요청했다면 캘린더와 초대를 생성하지 않는다.
  사용자가 **임시저장과 캘린더 등록을 함께 요청한 경우**에는 검증된 journal로
  `python3 leave_calendar.py --action draft-event --journal PRIVATE_JOURNAL --profile PRIVATE_PROFILE --nickname NICKNAME --email CORPORATE_EMAIL`
  를 실행하고 아래 생성 흐름을 진행한다. 실제 결재가 완료된 것으로 설명하지 않는다.
  현재 실제 결재 상신 실행은 구현되지 않았으므로 임시저장을 상신 완료라고 안내하지 않는다.
- “방금 상신한 휴가 캘린더에 넣어줘” → 아래 상신 확인과 캘린더 생성 흐름을 실행한다.
  “캘린더에만 추가”는 그룹웨어 상신 권한을 의미하지 않는다.

## 실행 맥락

- 휴가 상신 흐름의 **성공 확인 후** 이 스킬을 호출한다. 사용자가 그룹웨어에서 직접
  상신한 경우에는 동기화를 요청할 때 실행한다. 스킬만 설치하면 자동 감시되는 것은 아니다.
- 이 저장소에는 휴가 임시저장만 구현되어 있다. 상신 성공 응답이나 조회된 문서 키를 받아 이어서
  처리한다. 신청 화면 주소에서 저장/상신 endpoint를 추측하지 않는다.
- 별명은 사용자가 알려준 대화/메모리를 활용한다. 없거나 인물이 모호하면 질문한다.
  실명에서 별명을 추측하거나 다른 구성원의 별명을 기본값으로 사용하지 않는다.
- 참석자는 신청자의 **확인된 법인 이메일 한 개**. 표시 이름이나 로그인 ID만으로
  이메일을 조립하지 않는다. Google 연결 계정과 그룹웨어 신청자가 같은 사람인지 확인한다.
  생성자는 실제 Google 인증 계정으로 정해지며 이름을 임의 지정할 수 없다.
- 대상 캘린더 ID는 사용자 설정에서 읽는다. 공개 URL/iCal은 쓰기 권한을 주지 않는다.
  `.expense-state/leave-calendar.profile.json`에 `calendar_id`를 로컬로 보관할 수 있다.
  개인 설정/세션/휴가 원문은 Git에 추가하지 않는다. 인증은 기존 `expense.py auth` 흐름을 사용한다.

## 상신 확인과 일정 준비

1. 요청한 문서만 조회한다. HPD0550 사용 내역은 정상 세션으로
   `/personal/hpd0550/0hp00002`에 `ycYy`를 전달해 적용 기간을 얻은 뒤,
   `/personal/hpd0550/0hp00003`에 `ycYy`, `applyStDt`, `applyEdDt`를 전달한다.
   날짜/유형으로 찾은 후보가 여러 개면 문서 키를 확인한다. 과거 내역 전체를 등록하지 않는다.
2. `approState`가 `0`(결재진행) 또는 `1`(완료)이며 `reportCancYn=N`인지 확인한다.
   `5`는 임시보관이다. 임시보관/상신대기/반려를 성공한 상신으로 취급하지 않는다.
3. 저장소 루트에서 아래 helper로 표준 Google Calendar event body를 준비한다.
   인자 값은 실제 요청에서 얻으며 셸 문자열에 사용자 입력을 직접 보간하지 않는다.

   ```text
   python3 leave_calendar.py --year YYYY --link-key DOCUMENT_KEY --nickname NICKNAME --email CORPORATE_EMAIL --profile PRIVATE_PROFILE_PATH
   ```

   helper는 읽기만 수행한다. 연차는 `start.date`와 종료일 다음 날의 `end.date`로 종일
   일정을 만든다. 예를 들어 7일부터 18일까지면 Google 종료일은 19일이다.
   반차/반반차는 서버의 `startTm/endTm`과 `Asia/Seoul`을 사용한다.
   `반반차`처럼 오전/오후가 명시되지 않은 항목은 시간을 보여주고 제목 표기를 질문한다.
   점심시간이나 근무표를 가정하여 시간을 바꾸지 않는다. 실제 시간이 없으면 질문한다.

## 중복 확인과 생성

일정 요청 JSON이 준비되면 [Host Calendar Harness](references/harness.md)를 실행한다.
현재 Claude에 연결된 도구로 검색·생성·재조회하고 `calendar_harness.py verify`가
통과해야 완료다. 별도 OAuth나 다른 Claude 프로세스를 실행하지 않는다.

- 제목은 `{별명} {근태항목}`. 승인 대기 등의 접두사, 회의록, Meet 링크를 추가하지 않는다.
  휴가 사유/연락처는 공유 일정으로 복사하지 않는다.
- 출력의 `description`은 계정과 문서 키를 해시한 식별 표식이다. 캘린더에서 해당 표식을
  검색하고 모든 페이지를 확인한 뒤 description의 정확한 일치를 확인한다.
  최초에는 해당 휴가 기간으로 조회하되, 재시도나 날짜 변경 이력이 있으면 범위를 넓혀
  이전 일정도 확인한다. 기존 수동 일정도 별명·기간으로 조회하고 후보의 참석자를 재조회한다.
- 같은 표식 한 건이면 내용을 확인하고 재사용한다. 다른 기간/참석자이거나 수동 일정과
  겹치는 후보가 있으면 질문한다. 기존 일정을 임의 수정·삭제하지 않는다.
- `id`를 지원하는 연결 도구에서는 출력된 고정 event ID를 그대로 사용한다.
  먼저 동일 ID를 조회하고 없을 때만 생성한다. 조회 실패가 인증/권한 오류면 없음으로
  간주하지 않는다. 생성 중 응답 유실/409는 같은 ID를 다시 읽어 내용으로 판정한다.
- 연결된 Calendar 생성 도구의 실제 스키마를 확인하여 body를 매핑한다.
  연차는 **종일 date 필드 지원이 필수**다. 도구가 dateTime만 지원하면 자정 시간 일정으로
  대체하지 않는다. 이미 승인된 종일 생성 가능한 연결이 없으면 그 제약을 알리고 생성은 보류한다.
- 일반 이벤트로 생성하고 참석자는 신청자 한 명만 전달한다. 실행 계정을 자동으로
  참석자에 추가하는 도구라면 추가를 끈다. 참석자의 수락 상태를 강제로 accepted로 설정하지 않는다.
  초대 전송 옵션이 있다면 사용자가 요청한 참석자 초대에 맞게 설정한다.
- 생성 권한 오류나 응답 유실이면 휴가를 다시 상신하지 않는다. 표식 검색으로 생성 여부를
  확인하고, 성공 여부가 불명확한 상태에서 무조건 재생성하지 않는다.
- 반환된 event ID로 다시 읽어 대상 캘린더, 제목, 종일/시간 범위, 참석자 한 명과 표식을
  확인한 뒤 링크를 안내한다. 초대 기록과 참석자의 실제 수신함 반영은 구분한다.
  사용자가 휴가 저장과 캘린더까지 요청했다면 두 결과가 모두 확인되어야 완료다.

사용자가 실제 휴가 건을 지정하지 않고 스킬 구성을 요청했다면 운영 일정이나 테스트 초대를
생성하지 않는다. 완료 보고에서 스킬 작성, 조회 검증, 실제 일정 생성 검증을 구분한다.
